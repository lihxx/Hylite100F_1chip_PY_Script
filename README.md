# HYLITE1237 上位机寄存器功能/用法 + HYLITE_IO 核寄存器 + 数据包格式（速查）

> 适用：`Module_10kHz`（2×8 模块，16×HYLITE100F，32 条数字链）+ `Hylite100F_10K_script` Matlab 脚本。
> 范围：包括**上位机（Matlab）实际使用**的寄存器、**HYLITE_IO 核相关**寄存器/端口的用法，以及**寄存器命令包与回传数据流格式**。
> 版本 V1.0

约定：

- 寄存器访问=UDP(RBCP 写)，目标 IP `192.168.10.16`，端口 **4660**；数据回传=TCP 端口 **24**。
- “写 255”/“写 1”＝给某内部电平位拉高，“写 0”＝拉低；多数寄存器是电平，不是脉冲。
- 脚本里 `fwrite(u,[FF 80 51 1, 0,0,0,8,[0]])` 表示向地址 `0x0000_0008` 写 `0x00`（32bit 地址大端，见 §4.1）。

## 1. Matlab 实际使用的寄存器

### 1.1 一览表（按使用场景分组）

| 地址 | 名称 | 常用写值 | 作用 | 使用脚本 |
| --- | --- | --- | --- | --- |
| 0x00 | rstb_matlab 拉低 | 0xFF | 装载 GDAC 560bit 并准备自动上传 | init/config1/Left/Right |
| 0x01 | rstb_matlab 拉高 | 0xFF | 触发 GDAC 自动移位上传（结束后 LOAD_SPI 锁存） | 同上 |
| 0x08 | rstb_chip_t | 0→0xFF | 芯片复位输出（0 复位，0xFF 释放）；随后配置 | 所有脚本 |
| 0x0A | gate_t | 0 / 0xFF | gate 差分：配置阶段=0，工作阶段=0xFF | 所有脚本 |
| 0x0B | fifo_rst | 0xFF→0 | 复位 DDR3 存取通路/取数 FIFO（收尾清流水） | read_3 / Left / Right / ArrayRead |
| 0x0D | array_config_en | 0→0xFF | 像素阵列 SPI 自动上传使能（先 0 装载 13bit 模式，再 1 上传） | Left/Right |
| 0x0E | arrConfigSelect | 0~31 | 像素 13bit 模式（编码见 §1.3） | Left/Right |
| 0x0F | frame_G（=IO 核 LD） | 0xFF→0 | **取数门控**：为高期间每帧取数窗数据写入 DDR3 | read_3 / Left / Right / ArrayRead / 10frame |
| 0x10~0x55 | GDAC_udpreg 70B | 70B 连续写 | 芯片 560bit 全局配置缓冲（30B GDAC+40B 帧逻辑） | init/config1/Left/Right |
| 0x91 | LD_BIT | 0xFF→0 | bitslip 位对齐装载（正式取数前执行） | read_3 / Left / Right / ArrayRead / 10frame |
| 0x92 | LD_POS | 0xFF→0 | 位置装载（可不用） | 同上 |
| 0x93 | LD_HASH | 0xFF→0 | hash 对齐装载（在 LD_BIT 之前做） |
| 0x94 | ddr_rd_start | 0xFF→0 | 从 DDR3 读回并走 TCP:24 上传（拉高≥0.5~1s 再拉低，然后 fread） | 同上 |
| 0x116 | frame_rst | 1（常驻） | 帧计数器运行开关：1=产生 ~10kHz frame（=0 时停振） | 所有读图脚本 |
| 0x117 | MM_EN | 1（常驻） | 640 MHz 时钟输出使能（CLK_P/N0/1，IO 核 clkref 同源） | 配置完成后置 1 |
| 0x200~0x21F | probe_out0~31 | 1→0 每步一次 | 32 条链 IDELAY tap 步进（每 0→1 脉冲 tap 减 1，0~31 循环） | delay_2（经 countdownN_loop） |
| I2C 0x0002_0000 | I2C 主控制器 | 见 §1.4 | 通过 PCA9574（U33/U32）控制芯片 CS0~15 | 所有脚本（经 IIC_CS） |

> **当前无逻辑作用**的地址（兼容保留）：0x02/0x03/0x04（手动 SPI）、0x05（config_mod）、0x06（cs_t，CS 实际由 I2C 给）、0x07（refresh_t）、0x09（readout_from_pc）、0x0C（data_mux）。写不写都不影响功能。

### 1.2 控制与取数寄存器详情

| 地址 | 名称 | 功能与用法 |
| --- | --- | --- |
| 0x08 | rstb_chip_t | 输出 `RSTB_CHIP`（低有效芯片复位）。开机后脚本：`0x08=0`（复位）→ `0x08=0xFF`（释放），再做配置。 |
| 0x0A | gate_t | 芯片 gate。按芯片工作模式：配置(CS=0,gate=0) / 计数测试(0,1) / 工作(1,0/1)。脚本在 GDAC/阵列配置时写 0，正式取数前写 0xFF。 |
| 0x0B | fifo_rst | 复位数据通路/取数相关 FIFO。每次读图结束写 `0xFF`→0 清空流水（脚本在 fread 后做）。 |
| 0x0F | frame_G → LD | 正式取数开关。写 0xFF 拉高，IO 核在后续每个 frame（10 kHz）执行 13,824 拍(clk160M)取数窗并把 32 链数据写入 DDR3；写 0 停止。脚本一般拉高 0.5~1 s 再拉低，捕获若干帧。 |
| 0x116 | frame_rst | 帧计数器门控。**必须为 1** 才有 ~10 kHz frame 输出（frame=0 时计数器被清零停振）；GDAC 配置完成后脚本写 1 并保持。 |
| 0x117 | MM_EN | 640 MHz 时钟输出使能（BUFGCE CE）。=0 时 CLK_P/N0/1 无输出（芯片无时钟、取不到数）。配置完成后脚本写 1。 |
| 0x94 | ddr_rd_start | 拉高后 DDR3 中已捕获数据经 64→8bit FIFO 持续送 TCP:24；脚本拉高 0.5~1 s 后拉低，随即 `fread(t)` 收数。 |

推荐流程（脚本模板）：
`0x116=1`（帧运行）→ `0x117=1`（时钟输出）→（如需要）`0x93/0x91/0x92` 对齐 → `0x0F=255` pause(≥1s) `0x0F=0`（采集）→ `0x94=255` pause(0.5~1s) `0x94=0`（回传）→ `fread(TCP)` → `0x0B=255→0`（清流水）。

### 1.3 GDAC / 阵列配置上传

**GDAC/帧逻辑（560bit）上传**——数据源：`GDAC_regVcali1u_LowSpeed_128Gclk.xlsx`（或 LowSpeed / Init_PLL）第 1 列 70 字节（40B 帧逻辑在前 + 30B GDAC 在后，上传顺序为 word2 最先）。

1. 一条 UDP 写命令：地址 0x10、长度 70、数据 70B（`fwrite(u,[FF,80,51,70,0,0,0,0x10,GDAC_reg])`）。
2. 写 `0x00=0xFF`：装载缓冲并初始化上传计数器。
3. 写 `0x01=0xFF`：在 clk600k 下自动左移 560 拍（最高位先出）送出 `ARRAY_IN0/1`+`CLK_SPI`，移完后 `LOAD_SPI` 输出 1 个时钟正脉冲（芯片锁存）。整个上传 ≈1 ms，脚本 pause(2) 等待。
4. 上传结束后 `frame_gate` 置位、把 `0x116` 置 1，帧逻辑开始运行。

**像素阵列上传**——`0x0E` 选 13bit 模式，`0x0D` 触发：

1. 写 `0x0E=模式值`（下表）。
2. 写 `0x0D=0`（装载）→ 写 `0x0D=0xFF`（自动移位 106,496 拍 ≈0.18 s，两半 array_in 相同，结束产生 REFRESH 脉冲）。
3. 完成后写 `0x0D=0`。

`0x0E` 编码（5bit，代码 case）：bit 组合决定 电压刻度(VCali)/电流刻度(ICali) · Cal 使能 · 增益 Auto/M/H/L · CDS 使能/旁路；脚本当前用值 **8**（VCali+Cal En+AutoGain+CDS disE）做电压刻度注入测试；完整 0~31 模式含义与 13bit 码字见大文档 §5.3 表。

### 1.4 I2C：CS0~15 控制（PCA9574，U33/U32）

- FPGA I2C 主控制器基址 **0x0002_0000**；低 3 位为核内寄存器：0x0=分频低、0x1=分频高、0x2=控制(0x80 使能)、0x3=发送数据、0x4=命令（bit7 STA/bit6 STO/bit5 RD/bit4 WR/bit3 ACK）。
- 一次“写寄存器”事务 = 依次 UDP 写偏移 0x0~0x4（见 `IIC_CS.m`）：

  `0x0=61, 0x1=0`（SCL≈400kHz）→ `0x2=0x80`（使能）→ `0x3=器件写地址` → `0x4=0x90`(STA+WR) → `0x3=目标寄存器号` → `0x4=0x10`(WR) → `0x3=数据` → `0x4=0x50`(STO+WR)。

- 板级器件：

  | 器件 | I2C 写地址 | 管理的片选 | 配置寄存器 | 输出寄存器 |
  | --- | --- | --- | --- | --- |
  | U33 | 0x40 (hard_addr1=64) | CS0~7（模块左半） | 0x04（写 0=输出使能） | 0x05（bit i↔CSi） |
  | U32 | 0x42 (hard_addr2=66) | CS8~15（模块右半） | 0x04 | 0x05 |

  用法：输出寄存器写 **0xFF=该组 8 片全部选中**，**0x00=全部关闭**；`Module_ArrayConfig_Left_4.m` 只操作 U33、`Right_5.m` 只操作 U32，实现左/右半独立配置读出。

### 1.5 延时与对齐（HYLITE_IO 直接相关，见 §2）

- 0x200-0x21F probe_out0-31：由 `countdown0_loop.m … countdown31_loop.m` 使用，形如 `countdownN_loop(u, target)`：每步写 1→写 0（10ms 间隔）＝一次 tap 步进，内部以 `current=(current-1) mod 32` 走到目标值 target(0~31)。链号映射：链 2k/2k+1 ↔ 芯片 k+1 的 data0/data1（k=0 起）。
- delay_2 脚本依“数字链图像”定标给每条链设不同 target（成对相同值居多），链与芯片 data0/data1 一一对应。
- 对齐步骤在正式取数前：LD_HASH(0x93)（可选）→ LD_BIT(0x91)（必需）→ LD_POS(0x92)（可选）各拉高 10ms~1s 再拉低；随后 LD(0x0F) 取数、0x94 回传。

## 2. HYLITE_IO 核相关寄存器与端口

HYLITE_IO_Core（`HYLITE_IO_Core.v`）是 32 路串行收数核：每路 = (延时对齐)+(高速采样)+bitslip(位对齐)；核外完成 13bit 重组与 DDR 写入。下表是**由寄存器驱动的 IO 核端口/信号**。

| 寄存器/源 | IO 核端口 | 核内行为 | 用法 |
| --- | --- | --- | --- |
| 0x200+N probe_outN | probe_out0~31 | 上升沿产生 1 拍 `delayN_ce` → 第 N 链 CE 步进 ⇒ **每脉冲 tap−1**，5bit 0~31 自动回绕 | 手动/脚本逐步设 tap（§1.5）；tap 决定该链采样点 |
| 0x300+N xprobe_outN | xprobe_out0~31 | 上升沿使第 N 链 ISERDES 执行一次 BITSLIP | 手动单步位对齐；当前脚本未用 |
| 0x0F frame_G | LD | LD=1 且 frame 到来 → F_COUNT 状态机执行 13,824 拍(clk160M)取数窗，逐拍打包 32 链×8bit=256bit，`data_fifo_rden` 有效、输出写 DDR3 写 FIFO | 正式取数开关（§1.2） |
| 0x91 LD_BIT | LD_BIT | LD_BIT=1 且 frame=1 → F_BIT 状态机对该帧做 bitslip 对齐装载（自对齐回路有效） | 正式取数前的位对齐；脚本先 0x91 后 0x0F |
| 0x92 LD_POS | LD_POS | LD_POS=1 且 frame=1 → F_POS 状态机（位置装载） | “可不用”|
| 0x93 LD_HASH | LD_HASH | LD_HASH=1 且 frame=1 → F_HASH 状态机（hash 对齐装载） |
| 0xA1 delay_rst | fifo_rst（IO 核） | 异步复位 IO 核数据通路（含 IDELAY 清零语义） | 需要时 0xFF→0 脉冲 |
| — frame_t（内部） | frame | 帧同步输入（~10kHz）；LD_HASH/BIT/POS 状态机都需 frame=1 才触发 | 由 0x116 使能 |
| — 内部 readout_t | readout | 与 clk_cnts 关联（代码窗口条件近似常高） | 一般不需操作 |
| 0x09&&TESTPIN0 | rstb_matlab | 核内未使用 | 不操作 |
| ~RST_B（板上） | REGRST / clkIdy | REGRST=系统复位取反；clkIdy=clk200（IDELAY 控制时钟） | 不操作 |

关键参数（V1.0 工程）：clkref=clk640M、cgclk=clk400（IDELAYCTRL REFCLK=400.0）、clk_div=clk160M（主逻辑/取数窗时钟）；每帧窗 13,824 拍 ⇒ 每链每帧原始 13,824B（含帧头余量，像素有效 106,496bit 从帧头模板后开始）。

### 2.1 IO 核联调推荐步骤

1. `0x117=1` 时钟输出；`0x116=1` 帧运行；gate/CS 按工作模式就位（CS 经 I2C 给 1）。
2. 数字链/模拟图看数据乱 → 用 `countdownN_loop(u,x)`（0x200 系）调各链 tap 使采样点对准；必要时 xprobe(0x300 系)做 BITSLIP。
3. 正式取数前：`0x91(LD_BIT)` 拉高 10ms~1s→0（可选 0x93 在其前、0x92 在其后）。
4. `0x0F=1` 采集（写 DDR3）→ `0x94=1` 回传 TCP → 上位机按 §4.2 解析。

## 3. 寄存器命令包格式（UDP → FPGA）

### 3.1 RBCP 写命令（端口 4660）

| Byte | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 … 8+L−1 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 含义 | 0xFF | 0x80(写) | 0x51 | 长度 L | 地址[31:24] | [23:16] | [15:8] | [7:0] | L 字节数据 |

- 地址为 32bit **大端**，一字节一地址、数据 8bit。
- 例① 单字节写（rstb_chip=1，地址 0x08 数据 0xFF）：
  `[FF 80 51 01 00 00 00 08 FF]`
- 例② 70 字节批量写（GDAC，0x10 起）：
  `[FF 80 51 46 00 00 00 10 <70 字节数据>]`
- 例③ I2C 事务（PCA9574 输出寄存器写 0xFF，地址 0x0002_0000+偏移）：
  `…[0,2,0,0,61]`、`…[0,2,0,1,0]`、`…[0,2,0,2,128]`、`…[0,2,0,3,64]`、`…[0,2,0,4,144]`、`…[0,2,0,3,5]`、`…[0,2,0,4,16]`、`…[0,2,0,3,255]`、`…[0,2,0,4,80]`
- 地址注意：`[…,0,0,1,0x17,…]`＝0x0000_0117（不是 0x0001_0017）；脚本注释常写成“rstb_chip”等，属遗留，忽略。

### 3.2 RBCP 帧内地址小结（本文件涉及的写地址）

0x00/0x01（GDAC 触发）、0x08、0x0A、0x0B、0x0D、0x0E、0x0F、0x10~0x55（GDAC 数据）、0x91~0x94（对齐/回传）、0x116、0x117、0x200~0x21F（tap 步进）、0x0002_0000+0~4（I2C 主控制器）。

## 4. 回传数据流格式（TCP:24，FPGA → 上位机）

数据是 **DDR3 读回原始字节流**，无应用层包头/校验/长度域；0x94=1 期间持续发送直到读空，上位机按定长帧块 + 帧内特征模板定位来切分。

### 4.1 字节交织（32 链）

每 clk160M 拍，IO 核打包 32 条链 × 8bit = 256bit = 32 字节。因此流中：

- 第 1、33、65、… 字节 ⇒ 链 0（对应 `data_p0/probe_out0`）；
- 第 2、34、66、… 字节 ⇒ 链 1；…；第 32、64、… 字节 ⇒ 链 31。
  （Matlab：`ARc=t1(c:32:end,:)`，见 `D_P1.m` 23-54）

### 4.2 帧结构与定位

- 每帧每链的取数窗 = 13,824 拍 ⇒ **每模块帧块 ≈ 13,824 × 32 B = 442,368 B**（= 每芯片 2 链 × 27,648 B × 16 芯片）；多帧脚本按 `27648×16 B/帧` 切帧（`Module_ArrayRead_10frame_GIF.m` 的 RAW2_1…RAW2_10 切片）。单帧脚本缓存常数（如 430,400B）为经验值。
- 每链一帧的有效像素数据 = 128×2 列 × 128 行? 换算：**每链 8,192 像素 × 13 bit = 106,496 bit**（`D_P1.m`：`d1=AR1T(pos:pos+106495)`）。
- 帧起始定位：每链位流开头约 800 bit 内用 **44 字节特征模板**匹配（`targetstr=[FF×8, 00×8, FF×8, 00×8, FF×12]`，352bit，见 `D_P1.m` 第 5 行）；命中位置即该链 `pos`（全局变量 `pos1_0…pos16_1`，由数字链图像步骤定标），随后截取 106,496 bit 为一帧数据。
- 13bit 重组（离线）：每 13bit = 增益 2bit(g<1:0>)+ADU 11bit(d<10:0>)（MSB 先出）；再按 32 列组×256px 结构恢复像素矩阵，图像排序修正见 `DP3/DP3Z/arr_Mapping.m`。

### 4.3 传输流程与建议

1. 采集：`0x0F=1` 期间每 ~100μs（10kHz 帧率）写入一个帧块到 DDR3；拉高时间 × 帧率 = 捕获帧数（受 DDR3 容量限制，超出会覆盖最旧帧）。
2. 回传：`0x94=1`，读回并走 TCP:24；`fread` 前先设 `InputBufferSize ≥ 需要帧数 × 442,368B`（多帧脚本用 276,480×32≈8.8MB）。
3. 读图后写 `0x0B=0xFF→0` 复位流水，再开始下一轮。

## 5. 注意事项

1. **0x117(MM_EN) / 0x116(frame_rst) 的注释**在脚本里被写成 “rstb_chip”，实际分别是 640M 时钟输出使能与帧运行开关；两者都必须为 1 才能正常取数。
2. **CS 不通过寄存器 0x06**：FPGA CS0~15 引脚为高阻，芯片片选由 PCA9574(I2C 0x0002_0000)给出。
3. **probe_out 方向**：每次 1→0 脉冲对应 tap−1（0→31 回绕），与旧文档“加 1”字面相反；`countdownN_loop` 内部模型已与此一致，直接调用即可。
4. **LD_HASH/LD_POS**：流程在 LD_BIT 前/后各做一次；V1.0 IO 核中 F_HASH/F_POS 的执行支路未接出，效果以实测为准，**LD_BIT(0x91) 是对齐步骤**。
5. **帧起始模板与窗口长度**是离线定标产物：数字链步骤（`Module_GDAC_read_3`/D_P1）找到的 `pos1_0…pos16_1` 会保存在 Matlab 工作区供后续 DP3/DP3Z 使用，**脚本 1→6 需在同一 Matlab 会话连续运行**（或先跑定标再跑取数）。
6. 修改 xlsx 中帧逻辑/延时配置（尤其涉及 13bit 边界与 LOAD 时序）后，需重新定标帧起始位置，否则图像错位。
